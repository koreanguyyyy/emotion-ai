# emotion-detection-fusion

감정 에이전트의 **로컬 감지 모듈 — 표정 + 웹캠 심박 융합 버전**.

1학기 `emotion-detection`(DeepFace 표정 + Whisper 음성)과 같은 자리에서 동작하지만,
스트레스 계산을 2학기 `stressDetecter/emotion_pipeline`(블렌드셰입 + rPPG 심박 + 적응형 융합 + MSSD)으로 바꿨다.
**에이전트 서버(`emotion-ai-server`)와 백엔드(`emotion-backend`)는 수정 없이 그대로 쓴다.**
기존 `emotion-detection`, `stressDetecter` 폴더는 건드리지 않았다.

## 전체 흐름

```
[이 폴더]                                                    [그대로 재사용]
웹캠 ─┬─ MediaPipe 블렌드셰입 → 표정 정서가·각성도·신뢰도 ─┐
      │                     └→ 감정 라벨 (Tool 선택용)       │
      └─ 이마 색 변화 → rPPG 심박 → 평상시 대비 상승 ────────┤
                                                              ▼
                          적응형 융합 (표정이 애매할수록 심박 비중↑)
                                                              ▼
마이크 → Whisper → 최근 30초 발화      스트레스 지수 0~10 (부정·각성·기복)
                │                                             ▼ 6 이상 + 쿨다운 통과
                └──────────────→ emotion-ai-server /analyze (vad_stress 자리에 지수)
                                   LLM 보정 → 7 이상이면 추천 → TTS로 먼저 말 걸기
                                                              ▼
                                  emotion-backend 저장 · 키보드 피드백(l/d/s)
```

## 1학기 버전과 다른 점

| 항목 | 1학기 `emotion-detection` | 이 폴더 |
|---|---|---|
| 표정 | DeepFace 7감정 확률 | MediaPipe 블렌드셰입 52개 (2학기 파이프라인) |
| 심박 | 없음 | 같은 웹캠 영상에서 rPPG(CHROM) 심박 |
| 스트레스 | 감정 확률 × 고정 VAD 표 | 융합 정서가·각성도 + MSSD 기복 (`ai/stress_index.py`) |
| 개인차 | 없음 | 첫 1분 평상시 심박 보정 후 그 대비 상승분 사용 |
| 심박이 안 잡힐 때 | — | 2분 안에 보정 실패 시 표정만으로 동작, 나중에 잡히면 융합으로 복귀 |
| 심박 계산 | 2학기: 카메라 표기 fps 고정, 이마만, CHROM | 프레임별 실제 시각으로 리샘플링, 이마+양 볼, CHROM·POS 중 품질 높은 쪽 (`detection/rppg_timed.py`) |
| 신호 품질 | — | 심박 품질 0.40 미만은 버림, 얼굴이 절반 이상 안 잡힌 구간은 판단 보류 |
| 기록 | 로그 텍스트 | 1초 단위 `logs/session_*.csv` + 사건 `logs/events_*.csv` (논문 그래프용) |
| 카메라 번호 | 코드에 1로 고정 | `.env`의 `CAMERA_INDEX` (기본 0) |
| 무거운 의존성 | TensorFlow, DeepFace | 없음 |

## 스트레스 지수

```
지수 = 10 × ( 0.35 × 부정 정서 정도 + 0.35 × 심박 상승 정도 + 0.10 × 표정 각성 정도 + 0.20 × 기복 정도 )
  부정 정서 정도 = clip(-최근 10초 정서가(신뢰도 반영) 평균 / 0.4, 0, 1)
  심박 상승 정도 = clip( 최근 10초 (심박 − 평상시) 평균 / 20bpm, 0, 1)
  표정 각성 정도 = clip( 최근 10초 표정 각성도 평균 / 0.5, 0, 1)
  기복 정도      = clip( 최근 1분 MSSD(1초 평균) / 0.05, 0, 1)
심박을 모르는 구간(보정 실패·끊김)은 심박 항을 빼고 나머지 가중치(0.65)로 다시 나눈다.
```

2026-10-30에 심박 상승을 별도 항으로 바꿨다. 이전에는 심박이 적응형 융합 각성도 안에만 있어서, 표정이 뚜렷하면
심박이 30%만 반영됐다(찡그림 + 심박 +20 → 5.1점). 적응형 융합은 화면·기록용 융합 정서가·각성도에 그대로 쓴다.

합성 데이터 결과 (`tests/test_offline.py`, `tests/test_face_affect.py`):

| 상황 | 지수 | 개입 기준(6) |
|---|---|---|
| 평온 | 0.0 | 미만 |
| 심박만 +20bpm | 3.5 | 미만 |
| 부정 표정만 | 3.5 | 미만 |
| 부정 표정 + 심박 +20 | 7.0 | **이상** |
| 찡그림 + 심박 +20 (블렌드셰입부터 계산) | 7.0 | **이상** (변경 전 5.1) |
| 미소 + 심박 +20 (신남, 운동 직후) | 4.1 | 미만 |
| 표정이 3초마다 뒤집힘 | 2.5 | 미만 (기복 점수만 최대) |
| 심박 모름: 부정 표정만 | 5.4 | 미만 |
| 심박 모름: 부정 표정 + 표정 각성 | 6.9 | **이상** |

⚠️ 가중치·기준값은 모두 초기값이며 실제 데이터로 보정해야 한다. `.env`의 `STRESS_*`로 바꿀 수 있다.

## 표정: 개인별 무표정 기준선 (`ai/face_affect.py`)

2026-10-30 실행에서 무표정인데도 눈 찡그림·눈썹 올림 같은 값이 원래 0.4~0.5로 켜져 있어 신뢰도가 자주 1.0이었고,
실제로 지은 부정 표정(눈썹 안쪽 올리기 0.68)은 2학기 정서가 계산에 없어 정서가가 최저 −0.04에 그쳤다.

- 처음 `FACE_BASELINE_SEC`(60초) 동안 블렌드셰입 중앙값을 '이 사람의 무표정'으로 기록하고, 이후 평소보다 올라간 만큼만 읽는다.
- 정서가를 감정 라벨과 같은 계산에서 만든다: (행복 − 가장 강한 부정 감정) / 0.5. 라벨과 정서가가 같은 방향을 가리킨다.
- 합성 데이터(`python tests/test_face_affect.py`, 실제 기록의 무표정 프로필 사용): 무표정 신뢰도 1.00 → 0.14,
  눈썹 안쪽 올리기 정서가 0.00 → −0.39(슬픔), 찡그림 −0.92(분노), 미소 +1.00(행복).

### 슬픔 계산 보강 (2026-10-30)

슬픔 = 0.4 × 입꼬리 내리기 + 0.4 × 눈썹 안쪽 올리기 + 0.2 × 턱 올리기(`mouthShrugLower`, 아랫입술이 밀려 올라감).
실제 기록에서 턱 올리기가 0.6~0.84로 자주 나왔는데 이전 식(입꼬리 0.6 + 눈썹 0.4)은 이를 보지 않아, 입꼬리를 과장되게
내려야만 슬픔이 잡혔다. 턱 올리기는 생각할 때도 나오므로 입꼬리·눈썹 동작이 함께 있을 때만(그 합의 두 배까지) 센다.
합성: 은근한 슬픔(입꼬리 +0.05, 눈썹 +0.20, 턱 +0.50)의 슬픔 점수 0.11 → 0.20(라벨 기준 0.15 통과), 턱만 올리면 무감정.
대신 입꼬리 비중이 0.6 → 0.4로 줄어 입꼬리를 크게 내린 표정의 정서가는 −0.81 → −0.65로 약해졌다.

### 학습된 표정 모델 옵션 (`detection/face_model.py`, `tools/compare_face.py`)

HSEmotion `enet_b0_8_va_mtl`(AffectNet 학습, Apache-2.0, 8개 감정 확률 + 정서가·각성도). 공개 정확도는 AffectNet 8클래스 61.93%.
`pip install hsemotion-onnx`가 필요하고, 처음 실행 때 모델(약 16MB)을 `~/.hsemotion/`에 받는다.

| `.env` `FACE_MODEL` | 동작 |
|---|---|
| `compare` (기본) | 규칙 기반으로 동작하고, 모델 결과는 세션 CSV의 `model_*` 열에 나란히 기록만 |
| `use` | 모델의 정서가(× (1 − 무표정 확률))·각성도·라벨로 스트레스 지수와 에이전트 라벨을 계산 |
| `off` | 모델을 불러오지 않음 (설치가 안 돼 있어도 자동으로 off) |

비교: 측정 후 `python tools/compare_face.py` → 라벨 일치율, 라벨별 개수, 갈린 경우, 정서가 상관계수.
표정을 지은 시간을 메모했다면 `--script "70-80:행복,100-110:슬픔"`으로 메모 구간의 정답률도 낸다.
논문의 "규칙 기반(설명 가능, 개인 기준선) vs 학습 모델" 비교 자료로 쓴다.
모델은 무표정 기준선을 쓰지 않는다(남의 얼굴로 학습된 분류기). 실제 얼굴로는 아직 돌려보지 않았다(임의 이미지로 출력 형식만 확인).

## 웹캠 심박 (rPPG)

`detection/rppg_timed.py`가 2학기 `CHROMExtractor`를 대신한다. 2학기 코드(`emotion_pipeline/rppg.py`)는 그대로 두고 함수만 가져다 쓴다.

1. **실제 시각 기준**: 맥북 카메라는 15fps라고 알려주지만 실제로는 30fps로 보낸다(10초 측정, 중복 0개).
   fps를 틀리게 넣으면 심박이 비율만큼 어긋나므로, 프레임마다 실제 시각을 기록해 30Hz 간격으로 보간한 뒤 계산한다.
   처리 속도가 중간에 바뀌어도(30→18fps) 정답을 유지한다.
2. **이마 + 양 볼**: 영역을 넓혀 영역별 독립 잡음을 줄인다.
3. **CHROM + POS**: 둘 다 계산해 품질 높은 쪽을 쓴다. 최고값을 고르는 만큼 잡음 점수도 올라가서
   품질 기준을 0.40으로 다시 정했다(잡음만 넣은 40회 시험에서 0.35는 1.2% 통과, 0.40은 0%).

합성 데이터 결과 (`python tests/test_rppg_timed.py`, 정답 66bpm, 품질 기준 통과율):

| 맥박 세기 | 2학기 방식 (이마, CHROM, 0.35) | 새 방식 (이마+볼, 최고값, 0.40) |
|---|---|---|
| 약함 0.0015 | 2% | 32% |
| 중간 0.0025 | 54% | 97% |
| 강함 0.0040 | 99% | 100% |

통과한 값은 모두 정답 ±5bpm 안. 개선의 대부분은 이마+볼 합치기에서 나왔다(같은 조건에서 이마만 쓰면 61%).
단, 합성 데이터는 영역별 잡음을 독립으로 가정했다. 움직임·조명처럼 얼굴 전체에 같이 걸리는 실제 잡음에서는 이득이 작을 수 있다.

**2학기 `pipeline.py`의 fps 문제**: 카메라 표기 fps(15)를 그대로 쓰기 때문에, 실제 30fps 카메라에서
심박이 84bpm 미만이면 맥파의 두 배 주파수 성분 덕분에 우연히 정답 근처가 나오지만, 심박이 오르면
절반으로 나온다(정답 90 → 45, 105 → 54bpm). 스트레스로 심박이 오를 때 오히려 낮게 보이는 문제다.

### 절반·두 배 심박 오류 방지 (`ai/stress_index.py`)

4·5차 실행에서 품질을 통과한 심박이 진짜 값(약 100~108)과 그 절반(약 50~60) 두 무리로 갈렸다
(손목 맥박 104, 워치 101~107, 커피 마신 상태). 절반 쪽 봉우리는 배음이 아니라 독립된 성분이라 스펙트럼으로 고칠 수 없어서,
"심박은 몇 초 만에 두 배·절반이 되지 않는다"는 점으로 막는다.

- 평상시 심박 보정: 표본이 두 무리로 갈리고 둘 다 30% 이상이면 **높은 무리**의 중앙값. 근거는 이 두 번의 실제 기록뿐이다
  (4차는 낮은 무리가 56%로 더 많아서 '많은 쪽'을 고르면 틀렸다).
- 보정 후: 평상시의 0.4~0.6배, 1.7~2.3배인 추정은 버린다. 운동처럼 몇 분에 걸쳐 실제로 두 배가 되는 경우도 버려진다.
- 기록 재생 결과(보정 후 채택된 심박 중 100 근처 / 절반 근처): 4차 이전 71 / 122 → 새 규칙 71 / 7, `RESTING_HR=104` 지정 시 83 / 10.
- 가장 확실한 방법은 `.env`의 `RESTING_HR`에 워치로 잰 앉은 상태 심박을 넣는 것이다(보정 없이 바로 그 값 사용).

사용자가 **말로 대답하거나 웹 모니터 화면에 입력하면** 에이전트가 앞선 대화를 기억한 채로 답한다.

- 흐름: 개입 → 첫 메시지 읽기 → (음성 인식 / 웹 채팅) → 에이전트 서버 `POST /chat` → 답을 음성으로 읽기 → 반복
- "다른 노래 없어?"처럼 추천을 원하면 에이전트가 추천 도구를 다시 부르고, 새 추천은 그 개입의 추천으로 DB에 저장된다.
- 끝: 사용자가 "고마워, 이제 괜찮아"처럼 마무리하면 에이전트가 인사하고 끝냄 / 웹의 **대화 끝내기** / `CHAT_IDLE_SEC`(90초) 동안 말이 없을 때
- 대화 중에는 지수가 높아도 새로 말을 걸지 않는다 (events CSV에 `chat_skip`).
- 에이전트가 말하는 동안 마이크에 들어온 소리는 버린다(자기 목소리를 사용자 말로 알아듣지 않게). URL은 소리 내어 읽지 않는다.
- Whisper가 조용할 때 지어내는 문장("시청해 주셔서 감사합니다" 등)은 대화로 보내지 않는다.
- 대화가 없을 때 웹의 **대화 시작**으로 먼저 말을 걸 수도 있다.
- 대화 내용은 에이전트 서버의 `logs/chat_sessions.jsonl`에 남는다 (평가 자료).

```
# .env (모두 선택)
CHAT_ENABLED=true     # false면 예전처럼 한 번 말하고 끝
CHAT_IDLE_SEC=90
CHAT_TIMEOUT_SEC=40
CHAT_SPEAK_WEB=true   # 웹에 쓴 말에 대한 답도 음성으로 읽기
STT_MODE=vad          # 대화에는 말이 끝나면 바로 인식하는 vad 모드를 권장 (fixed는 10초씩 끊어 들음)
```
시험: `python tests/test_conversation.py` (25개), 에이전트 서버 `python tests/test_chat.py` (19개)

## 지난 대화 기억 (2026-11-04)
| 층 | 내용 | 기간 |
|---|---|---|
| 대화 안 | 지금 대화의 최근 메시지 | 40개 |
| 최근 발화 | 대화 밖 말까지 시각과 함께 그대로 (`SPEECH_HISTORY_SEC`) | 30분 |
| 혼잣말 요약 | 30분마다 대화 밖 말을 1~3줄 요약 (`SPEECH_SUMMARY_EVERY_SEC`, 잡음뿐이면 저장 안 함) | 7일 |
| 대화 요약 | 대화가 끝날 때(마무리·끝내기·무응답·새 관람객) 고민·감정·도움된 것을 3~5줄 요약 | 7일 |
- 에이전트가 먼저 말을 걸 때와 대화할 때 최근 요약 8개(`MEMORY_MAX`, `MEMORY_DAYS`)와 최근 발화를 프롬프트에 넣는다
  → "어제 말씀하신 발표는 잘 끝나셨어요?"처럼 이어 간다.
- 기억 공간은 `user-<USER_ID>`. **'새 관람객'을 누르면 새 공간**으로 바뀌어 앞사람 이야기를 꺼내지 않는다.
- 저장: 에이전트 서버 `logs/user_memory.json`(요약 글만, 이 노트북 안). 끄려면 서버 `.env` `MEMORY_ENABLED=false`.
- 평소 켜 두면 대화 밖 혼잣말도 요약되므로, 쓰는 사람에게 알리고 쓴다.

## 동작 모드

| 모드 (`hr_mode`) | 뜻 | 각성도 | 개입 |
|---|---|---|---|
| `calibrating` | 평상시 심박 보정 중 | 표정만 | 보류 |
| `fusion` | 심박 보정 완료, 현재 심박 유효 | 표정 + 심박 적응형 융합 | 가능 |

심박을 모를 때는 '평상시 심박(0)'을 넣지 않고 표정 각성도만 쓴다. 0을 넣으면 표정 각성도까지 깎이기 때문이다.
